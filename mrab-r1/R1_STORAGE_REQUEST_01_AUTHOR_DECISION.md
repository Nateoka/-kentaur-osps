# R1-STORAGE-REQUEST-01 — поправка хранения запросов

Статус: явно разрешено автором 2026-09-16 в текущей задаче: «Да, отдельная поправка хранения».

В производной runtime-схеме удаляется только ограничение
`/$defs/call_usage/properties/request_bytes/maxLength = 20000`
из `r1_episode_record.schema.json`. Тип, обязательность, остальные поля и ограничения сохраняются.
Пять файлов схем в замороженном design-пакете не изменяются. `Schemas(storage_patch=False)`
позволяет воспроизвести исходную проверку; обычный runtime применяет именованную поправку в памяти.

Основание: полная обязательная история допустимого B0/C0 эпизода 32 превышает 20 000 символов
ещё до введения профиля и PREP. Ограничение хранения не должно заставлять обрезать отправленный запрос.
Машиночитаемый свидетель: `verification/REQUEST_CAPACITY_WITNESS.json`.

Это не изменение токен-бюджета: максимум входа остаётся 16384 токена;
лимиты task payload, PREP, ACTION, REPAIR, правила истории и вызовов не изменены.
Ограничение `visible_output` не снимается. Сырые ответы сохраняются отдельными событиями.
Runtime обязан фиксировать эту поправку в идентичности исполнения и отчётах проверки.
